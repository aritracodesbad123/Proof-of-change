Glossary

TermMeaning
Old side / new sideThe same dependent library tested twice: once with the old version of the upstream library, once with the new one. Nothing else differs.
UpstreamThe library being changed (for example pandas). The PR or release under review belongs to it.
DependentA library that uses the upstream. Its own tests are our test subject.
Real breakA test that passed in every old run and failed in every new run. This is a behavior change caused by the upstream change.
Import failureA test module that cannot even be loaded on the new side, so none of its tests can run. Counted per module.
Lost testsTests that passed before but could not run after, because their module failed to load. Not counted as real breaks.
Already brokenTests that failed before the change too. Not caused by the change.
FlakyTests whose result changes between runs on the same side. They are not trusted either way.
Error signatureThe error message with numbers and file paths removed, so identical failures group together.
GateAn automatic check by the runner that the run itself is trustworthy (right versions, same environment, enough runs). Required gates must pass for the result to count.
EvalNathan's independent check of the record (schema, versions, runs per side, threads, golden cases, citations). Any eval failure means the run cannot be trusted.
Golden caseA known example with a known answer. If the tool still gets the golden cases right, its answers on new cases are more believable.
StabilityShare of tests that gave the same result in every run on one side. 1.0 means fully repeatable.
CitationA file name, line number and quoted text from a run log that backs a statement in the report.
JUnit XMLThe machine-readable test result file pytest writes for each run.
FreezeThe exact list of installed packages and versions on each side.
